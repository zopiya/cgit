## 实现与三种部署

调用链：lighttpd rewrite → gateway.main → Basic/Bearer 身份解析 → Web/cgit、Git http-backend 或 LFS 文件接口。access 由 Gitolite 编译策略和带摘要的 identity.json 授权；SSH forced command 复用 Access，Git 更新由 Gitolite hook 约束。maintenance 独立运行 jobs CLI 与 Supercronic。

| 方案 | 当前能力和限制 |
|---|---|
| 个人内网 | 基础 Compose 默认 public、repos 只读、无账号/无 access 文件依赖；匿名 Web/Git/LFS 读取。端口默认绑定所有地址，内网隔离由宿主负责。宿主 SSH 写入自行受控；项目自带 SSH 尚强制依赖 access。 |
| 公开发布 | 基础 Compose + public 覆盖文件可用 Caddy HTTPS，不要求 access。只挂载明确公开的独立 repos/lfs 数据；两个实例必须使用不同项目目录、缓存、配置与密钥。默认固定 container_name 和端口不能直接并行复用。 |
| access 协作 | 基础 + access；SSH/maintenance 分别为可选 profile。匿名可见集、HTTP 凭据、SSH 公钥、仓库 Gitolite ACL。owner 标志保证管理身份存在，不直接授予所有仓库权限。 |

不要叠加 write 与 access：前者注入单账号秘密，与 access 配置检查冲突。public 覆盖只是 HTTPS 入口，不筛选数据。默认账号 write 覆盖是全站 private；若希望匿名读、认证写，显式设置 public。

## 已确认并修复

以下都是起点代码已有问题，不是登录增量引入；测试只使用临时合成数据。

1. **高：sync-in 路径越出仓库根。** runtime/jobs.py:run_sync_in 原先仅检查 repo.is_symlink，父级 group 是符号链接时可向根外 group/demo.git fetch/更新。新增 test_sync_rejects_symlink_parent 在修复前失败（未抛异常）。Git 目标与 LFS 目的路径现均复用 safe_path，逐段拒绝符号链接与遍历。该边界防错误挂载/目录配置；不声称防御拥有宿主目录写权限者的并发替换攻击。
2. **高：同步保留同长度损坏 LFS 对象。** 原先 destination 大小相同便跳过，能报告成功但留下错误字节。回归先写等长度 x 字节，修复前字节断言失败。现仅在大小及 SHA-256 都正确时复用，否则校验来源后原子替换。证据 artifacts/audit-reproduce.log 和 audit-jobs.log；此失败路径使用受控 LFS wrapper，另有真实客户端成功路径。
3. **高（运行阻断）：真实 LFS 同步 JSON 不兼容。** Git LFS 3.8.0 的 ls-files --json 输出 {"files": [...]}（无对象时 files:null），原代码按数组迭代，触发 AttributeError。原测试也伪造数组，未检测此错误。修正 envelope/元素类型解析，模拟输出与真实接口对齐，新增 test_sync_with_real_lfs_client，用真实 Git/LFS 与本地 bare LFS 存储同步非空对象。把新测试放到临时 HEAD 源码副本上，稳定复现 AttributeError（artifacts/audit-real-lfs-before.log）；修复后通过。
4. **中：远端 .lfsconfig 拒绝无效。** clone --no-checkout 后检查工作树文件必然漏掉 HEAD 中配置，可使 LFS 使用来源指定的其他端点。现先用 ls-tree 检查 HEAD 根目录，再运行 LFS；拒绝测试检查旧 refs 保持不变。修复前测试越过该检查并在 JSON 解析处崩溃（audit-lfsconfig-reproduce.log），修复后明确报 .lfsconfig。没有向外部恶意端点发请求，不宣称已证明秘密外泄。
